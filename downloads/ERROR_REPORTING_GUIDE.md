# 📋 Guía de Reporte de Errores - Booming Music

> **Creado:** Marzo 3, 2026
> **Versión:** 1.3.0+ (Debug builds)

---

## 🎯 Descripción

La APK de debug de Booming Music ahora genera **automáticamente** un archivo con todos los errores y fallos que ocurren durante el uso de la aplicación.

---

## 📁 Archivos Generados

La aplicación genera **dos archivos** en la carpeta Downloads de tu dispositivo:

### 1. `Downloads/BoomingMusic/debug.log`
- **Propósito:** Log detallado de TODAS las operaciones
- **Contenido:** Logs verbose, debug, info, warnings, errors
- **Tamaño máximo:** 5MB (luego rota a `debug_old.log`)
- **Formato:** Texto plano con timestamps

### 2. `Downloads/BoomingMusic/app-errors.md` ⭐
- **Propósito:** Reporte estructurado de ERRORES y fallos
- **Contenido:** Solo errores, warnings, crashes y excepciones
- **Formato:** Markdown estructurado con secciones
- **Se actualiza:** En tiempo real durante la sesión

## 🔍 Tipos de Errores Capturados

| Tipo | Descripción | Ejemplo |
|------|-------------|---------|
| **Errors** | Errores generales de la app | Excepciones no manejadas |
| **Warnings** | Advertencias que no causan crash | Deprecated API usage |
| **Crashes** | Fallos fatales que cierran la app | NullPointerException fatal |
| **StrictMode Violations** | Violaciones de políticas de Android | Disk read/write en main thread |
| **Network Errors** | Errores de red | HTTP 4xx/5xx, timeouts |
| **Database Errors** | Errores de base de datos | Query fallida, transacción rollback |

## 🚀 Cómo Usar

### 1. Instala la APK de Debug
```bash
# Build debug
./gradlew assembleDebug

# Instalar
adb install app/build/outputs/apk/debug/app-debug.apk
```

### 2. Usa la aplicación normalmente
- Todos los errores se registrarán automáticamente
- No necesitas configurar nada

### 3. Revisa los reportes
```bash
# Ver errores en tiempo real
adb shell cat /sdcard/Download/BoomingMusic/app-errors.md

# Ver log completo
adb shell cat /sdcard/Download/BoomingMusic/debug.log

# O usa un file manager en el dispositivo
```

### 4. Extrae los archivos para analizar
```bash
# Copiar a tu computadora
adb pull /sdcard/Download/BoomingMusic/app-errors.md ./errores-app.md
adb pull /sdcard/Download/BoomingMusic/debug.log ./debug.log
```

---

## 📱 Permisos Requeridos

La aplicación necesita permiso de almacenamiento para guardar los logs:

- **Android 10-12:** `READ_EXTERNAL_STORAGE`
- **Android 13+:** `READ_MEDIA_AUDIO` (ya incluido)

El archivo se guarda en una carpeta pública (`Downloads/BoomingMusic/`) para que puedas acceder fácilmente desde un file manager o ADB.

---

## 🔄 Rotación de Logs

### `debug.log`
- **Tamaño máximo:** 5MB
- **Acción:** Se renombra a `debug_old.log` y comienza uno nuevo
- **Objetivo:** Evitar llenar el almacenamiento

### `app-errors.md`
- **Tamaño:** Variable (depende de errores)
- **Acción:** Se sobrescribe en cada sesión
- **Objetivo:** Reporte fresco por sesión

## 🛠️ Para Desarrolladores

### Integrar en tu código

```kotlin
// Loggear un error
DebugLogger.e("TAG", "Mensaje de error")

// Loggear con excepción
DebugLogger.e("TAG", "Error detallado", exception)

// Loggear warning
DebugLogger.w("TAG", "Advertencia")

// Loggear crash
DebugLogger.logCrash(exception, "Contexto del crash")

// Loggear error de red
DebugLogger.logNetworkError(
    url = "https://api.example.com",
    method = "GET",
    statusCode = 500,
    errorMessage = "Server error"
)

// Loggear error de base de datos
DebugLogger.logDatabaseOperation(
    operation = "INSERT",
    table = "songs",
    success = false,
    details = "Constraint violation"
)
```

### Contadores de errores

```kotlin
val errors = DebugLogger.getErrorCount()
val warnings = DebugLogger.getWarningCount()
val crashes = DebugLogger.getCrashCount()
```

## 📊 Estadísticas de la Sesión

Al final de cada sesión (cuando cierras la app), el reporte incluye:

- Total de errores por categoría
- Timestamp de inicio y fin
- Información del dispositivo
- Versión de la app
- Rutas de los archivos de log

---

## ⚠️ Importante

1. **Solo en Debug Builds:** Este sistema solo está activo en builds de debug (`BuildConfig.DEBUG = true`)

2. **No usar en producción:** El logging continuo puede afectar el rendimiento y llenar el almacenamiento

3. **Privacidad:** Los logs pueden contener información sensible. No compartas los archivos públicamente sin revisarlos.

4. **Almacenamiento:** Si usas la app por mucho tiempo, los logs pueden ocupar varios MB. Limpia periódicamente.

---

## 🐛 Solución de Problemas

### Los archivos no se generan
- Verifica que sea una build de debug
- Revisa que la app tenga permisos de almacenamiento
- Revisa los logs de Logcat: `adb logcat -s DebugLogger:*`

### Los archivos están vacíos
- Puede que no hayan ocurrido errores
- Revisa si el logger se inicializó: busca "Debug logger initialized" en el log

### Error "Failed to write log"
- Verifica espacio disponible en almacenamiento
- Revisa permisos de la carpeta Downloads
